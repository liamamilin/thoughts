# Thoughts · 个人思考档案

这是一个持续更新的**个人想法库 / 讨论库 / 结论库**。把讨论中的观察、推理、证据、分歧、暂定结论和待验证问题保存为可追溯的文章，而不是只保存一句观点。

- 网站首页源文件：[`index.html`](index.html)
- 第一篇文章：[在中国，普通人获得可靠生活为什么这么难？](posts/2026-11-19-ordinary-life-reliability.html)
- 原始讨论纪要：[`notes/2026-11-19-ordinary-life-reliability.md`](notes/2026-11-19-ordinary-life-reliability.md)

## 每次新讨论怎么入库

1. 新建 `notes/YYYY-MM-DD-short-slug.md`，作为可独立阅读的完整文章，按下方写作规范组织关键结论及论据。
2. 创建对应的 `posts/YYYY-MM-DD-short-slug.html` 阅读页，复用 `assets/site.css`。
3. 在 `index.html` 的 `.listing` 中新增一张 `.entry` 卡片，配置分类、检索关键词、标题和标签。
4. 提交 Git，保留后续修订记录。更改结论时说明证据更新依据。

该版本采用无框架静态 HTML / CSS / JavaScript，不依赖构建工具或服务器，便于简单维护。首页搜索为本地文章索引搜索，并非全文检索。

## 发布到 GitHub Pages

仓库使用 `.github/workflows/deploy-pages.yml` 中的 GitHub Actions 工作流，在 `main` 分支的静态网站文件更新时自动部署。发布状态以仓库 Actions 中的实际运行结果为准。

网站地址：`https://liamamilin.github.io/thoughts/`。也可本地打开 `index.html` 预览。

## 内容原则

- 明确区分：观察事实 / 机制推断 / 规范判断 / 待验证结论。
- 不把个别例外伪装成能推翻总体趋势的证据，也不为突出观点而杜撰比例。
- 保留讨论者真正关心的结论，不靠过多机械限定稀释它。
- 使用 [Independent Judgment Skill](https://github.com/liamamilin/skills/blob/main/skills/independent-judgment/SKILL.md) 作为论证质量规范。

## 文章写作规范（后续所有新文章均适用）

目标是把**讨论所涉及的问题、结论及其支撑逻辑**写成一篇读者可以独立理解的文章，而不是保存聊天流水账。

1. **保留论证**：清楚交代现实问题、关键概念、具体例子、因果机制、必要证据、主要结论和行动建议（适用时）。不能因为追求精简而只留下口号或结论。
2. **去除对话元叙事**：正式正文不写“本轮讨论”“我们刚才纠正了”“第几次更新”“模型之前说错了”等对话过程、争执、版本修改和自我反思；这些交给 Git 历史记录。
3. **避免防御性表达**：不为预防想象中的反驳而堆砌“不是百分之九十五/九十九”或“并非绝对”等无关限定；只有确实改变命题范围或结论强度的不确定性才简明说明。
4. **尊重已确定的概念与力度**：不得擅自把“基本生活”改为“高质量生活”，或把“长期很难改变”改写成“永远不可能改变”再反驳。新证据需要修正时，准确改写并解释实际依据。
5. **文章末尾必须有“核心结论”**：集中列出最重要的三至六项可独立理解的判断，包括关键机制、长期影响和行动原则（若涉及）；每项言之有物，不添加新论据，也不机械重复整个正文。
6. **发布一致性**：Markdown 原文与 HTML 阅读页的关键论点和末尾总结一致；新文章同时更新首页索引。提交后重新读取核对，不把 Git 提交成功等同于线上部署成功。

推荐行文结构：**现实问题 → 机制与支撑依据 → 主要结论及影响 → 可执行建议（如适用） → 核心结论**。根据题目调整章节，不强制套模板。
